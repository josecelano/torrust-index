# Tree Snapshots

Step-by-step Graphviz DOT snapshots of the internal **G-Tree** and **V-Tree**
generated by the `tree_snapshot` example.

Files in this folder are **generated** — commit them if you want a reproducible
diff of how the trees evolve across code changes, but do **not** edit them by
hand.

## Regenerating

```bash
cargo run --example tree_snapshot
```

## Rendering (requires [Graphviz](https://graphviz.org/))

SVGs are written to a separate `svg/` subfolder so they stay out of the way of
the source `.dot` files.

### Individual SVGs (one file per step × tree type)

```bash
./docs/snapshots/render-svg.sh
```

### All-in-one storyboard SVG

`render-storyboard.py` produces `svg/storyboard.svg` — a single self-contained
SVG with every step laid out in a scrollable grid:

| Column | Content        |
| ------ | -------------- |
| Left   | Step label     |
| Centre | G-Tree diagram |
| Right  | V-Tree diagram |

Each row is one observation step. Open the file in any browser or SVG viewer
and scroll vertically to trace the tree evolution.

```bash
./docs/snapshots/render-storyboard.py          # from repo root
cd docs/snapshots && ./render-storyboard.py    # from inside the folder
```

Both scripts can also be run from inside the `docs/snapshots/` directory.

## Naming convention

| Pattern                       | Description                              |
| ----------------------------- | ---------------------------------------- |
| `step_NN_<label>_gtree.dot`   | G-Tree snapshot after step NN            |
| `step_NN_<label>_vtree.dot`   | V-Tree snapshot after step NN            |
| `step_NN_<label>_summary.txt` | Text table of all G-nodes (V-tree order) |

## What the diagrams show

### G-Tree (`_gtree.dot`)

The **G-Tree** is a binary range-split tree over the coordinate space. Every
node covers a half-open interval `[lo, hi)`.

| Colour | Meaning                                         |
| ------ | ----------------------------------------------- |
| Green  | Terminal G-node with an active V-Tree entry     |
| Grey   | Terminal G-node with **no** V-Tree entry (rare) |
| Yellow | Internal G-node (both children present)         |
| Orange | Semi-internal G-node (one child present)        |

Each node label contains:

```
G<id>  [lo, hi)
d=<depth>  <state>  VEntry(<v-id>) or "no VEntry"
own=<own>  sum=<sum>
```

- `own` – value accumulated _directly_ at this node (observations that were
  routed to this node before, or after, it was split).
- `sum` – total value in the subtree rooted at this node (`own` + children's
  sums).

### V-Tree (`_vtree.dot`)

The **V-Tree** is the virtual intensity tree used for weighted sampling. Two
kinds of nodes exist:

| Shape            | Colour    | Meaning                                                         |
| ---------------- | --------- | --------------------------------------------------------------- |
| Box (blue)       | `#bbdefb` | **Entry** — leaf in the V-Tree; backed by a G-node              |
| Ellipse (purple) | `#e1bee7` | **Structural** — internal routing node that aggregates children |

Entry node label:

```
V<id> Entry
G<gid>  [lo, hi)  d=<depth>  <state>
intensity=<int>  exposed=<bool>  evict=<bool>
```

Structural node label:

```
V<id> Struct
intensity=<aggregated>  has_evict=<bool>
```

Edge labels show the cached child intensity (`i=<value>`).

## Worked example — 4-bit address space

The `tree_snapshot` example uses `GvGraph<u8, u32, 4>` (domain `[0, 16)`) with
`split_threshold = 2`. A node splits as soon as its accumulated sum exceeds 2
(i.e. ≥ 3 observations).

```
Step 00  initial-empty
  GTree: single root G0 [0,16)  own=0  sum=0  Terminal
  VTree: empty (no observations)

Step 01  obs coord=2, value=1
  GTree: G0 [0,16)  own=1  sum=1  Terminal

Step 02  obs coord=3, value=1
  GTree: G0 [0,16)  own=2  sum=2  Terminal

Step 03  *** SPLIT ① *** obs coord=2, value=1  (sum=3 > 2)
  GTree: G0[0,16) Internal  own=3  sum=3
           ├─L─ G1[0,8)  Terminal  own=0  sum=0
           └─R─ G2[8,16) Terminal  own=0  sum=0
  VTree: Structural root
           ├── Entry → G0  (the old, pre-split accumulation: own=3)
           └── Structural
                 ├── Entry → G1
                 └── Entry → G2

Step 04  obs coord=10, value=1   (routes to G2[8,16))
Step 05  obs coord=2,  value=1   (routes to G1[0,8))
Step 06  obs coord=3,  value=1   (routes to G1[0,8))

Step 07  *** SPLIT ② *** obs coord=2, value=1   G1 sum=3 > 2
  GTree: G0[0,16)  Internal  own=3  sum=7
           ├─L─ G1[0,8)  Internal  own=3  sum=3
           │      ├─L─ G3[0,4)  Terminal  own=0
           │      └─R─ G4[4,8)  Terminal  own=0
           └─R─ G2[8,16) Terminal  own=1

Step 08  obs coord=2, value=1  (routes to G3[0,4))
```
