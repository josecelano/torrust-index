## Phase 2 — Fitness for Inclusion

**Key finding: mudlark has zero usage in this codebase today.** There are no imports or references to `torrust_mudlark` anywhere in `src/` or `tests/`. It is added as a workspace member only.

### What it is actually for

ADR-M-036 ("Sentinel Integration API") reveals the full picture: mudlark is designed as **Layer 1** of a three-layer architecture for `torrust-sentinel` — a planned package described as a "Spectral Sentinel — hierarchical online subspace anomaly detector". The `packages/sentinel/` directory does not exist in this PR.

```
Layer 1: G-V Graph      ← mudlark (this PR)
Layer 2: Analysis Selector
Layer 3: Analysis Engine
```

The `torrust-sentinel` entry in `cargo-machete`'s ignore list (Phase 1 mystery) now makes sense — it's a forward reference to that yet-to-be-added package.

### Issues

- ❗ **No immediate use.** ~64k lines of code are added to this repo with no functional integration. The codebase becomes materially larger, slower to compile, and harder to audit with no user-facing benefit in this PR.
- ❗ **Dependency inversion.** `torrust-index` (a specific application) is being used to incubate what is effectively a general-purpose library + its own future application layer (`sentinel`). The natural ownership would be either:
  - A standalone published crate (it already has `publish = true`, `version = "1.0.0"`, and `cargo add torrust-mudlark` in the README install instructions)
  - A separate `torrust-primitives` or `torrust-algorithms` repo
- ❗ **Scope creep.** The PR description says "This data structure is general and should find use in future developments." That's a weak justification for a 64k-line addition to an index backend. Future developments can add future dependencies.
- ❓ **Why not publish it standalone first?** If mudlark is ready to ship at 1.0.0 with a stable semver API, formal spec, and 833 tests, it is ready to be its own crate on crates.io. It could then be a normal `[dependency]` in torrust-index when actually needed.
- ❓ **What is `torrust-sentinel` and when will it come?** If it's coming in the next PR, the argument for co-location is stronger. If it's speculative, this is premature.

### Resolution

**Accepted as-is for now, with a note.** The author is aware it doesn't fully belong here yet. It was built to solve real problems in this repo (and others), future integration is planned, and it can be extracted to its own repo/crate later once usage is established. We take this on faith and continue the review on code quality grounds.

## Phase 3 — Public API & `lib.rs`

### Structure

All source modules are `pub(crate)`. Types are re-exported flat from the crate root — one canonical path per type. This is the right pattern: downstream code uses `use torrust_mudlark::GvGraph` not `use torrust_mudlark::graph::GvGraph`.

Three-surface model (ADR-M-032) is clearly enforced:
- **Surface 1 (Prints):** `Cell`, `Node`, `Span`, `GState`, `Pewei`, `Layer`, `Transition`, `Terminal`, `Plateau`, `BasisEdge`, `GNodeId`, `VNodeId`, `BasisElement`, `ContourRange`, `ContourRangeEnergy`, `GNodeInfo`
- **Surface 2 (Film):** `GvGraph`, `Config`, all traits
- **Surface 3 (Emulsion):** all `pub(crate)` internals

### What's good

- `Config<V>` has no `Default` impl — intentional and documented. Good.
- `#[forbid(unsafe_code)]` at the crate root — enforced.
- ADR-M-036 D1 (`gnode_id` field on `Node`) is implemented.
- The trait decomposition is logical: `Accumulator` core, with `Attenuatable`, `Weighable`, `Proratable`, `Inspectable` as independent opt-in sub-traits that each unlock specific methods. The capability tree is well-documented.
- All built-in numeric types get blanket impls, so most users never touch the traits.
- `Rng` is a thin newtype over `rand_core::Rng` — keeps the `rand` ecosystem optional without locking users out.

### Issues found

1. **`build_plateaus()` and `debug_plateau_basis()` are `pub` but absent from `docs/api.md`.**
   - `build_plateaus()` is the fallback O(G log G) plateau recompute used when `dynamic-contour-tracking` is off — it's a legitimate public method but it needs to be in the API docs.
   - `debug_plateau_basis()` is documented inline as "exposes `pub(crate)` basis bookkeeping for integration tests". Its name and doc suggest it's a testing affordance, not a stable API surface. It should be `#[doc(hidden)]` like the `invariants` and `testing` modules, or gated behind `#[cfg(test)]`.

2. **Several `GvGraph` methods are `pub` but not in `docs/api.md`:**
   - `v_root()` — returns the V-Tree root handle
   - `depth_buffer()` — the gap between `depth_create` and `depth_evict`
   - `headroom()` — remaining capacity before budget
   - `soft_limit()` — computed soft budget ceiling
   - `is_ancestor_of()` — structural G-tree query (added for ADR-M-036)
   These all appear useful, but their omission from the API doc means the "docs/api.md is the definitive surface" claim is incomplete.

3. **`Node` API docs say it has fields `start`, `end`, `own`, `sum`, `depth`, `state`** (docs/api.md §4.1) but `Node` now also has `gnode_id` (from ADR-M-036 D1). The `docs/api.md` needs updating.

### Summary

The API architecture is sound and the surface model is well-enforced. The issues are documentation gaps — the implementation moved ahead of `docs/api.md` in a few places. No breaking or security issues.

## Phase 4 — Core Implementation

12 modules reviewed. Sizes: `arena`(168L) `gnode`(202L) `gtree`(122L) `observe`(174L) `split`(330L) `decay`(313L) `evict`(591L) `rebalance`(1478L) `vtree`(352L) `vnode`(269L) `graph_budget`(247L) `graph_query`(711L).

### `arena.rs`
Vec-backed arena with free-list reuse + u64 bitset occupancy. O(1) alloc/dealloc/get. `debug_assert` guards in dev, bare array access in release. ✅ Sound.

### `gnode.rs`
`GNode<C,V>` with `pub(crate)` fields. `GState` enum (Terminal / SemiInternal / Internal) derived from child pointers at query time — zero storage overhead (ADR-M-016). `uncovered_range()` for SemiInternal routing.  ✅ No issues.

### `gtree.rs`
`route_to_receiver()` iterative descent; `gnode_depth_from_interval()` via `trailing_zeros`/`f64::log2`; `recompute_g_sums()` upward walk; `recompute_g_sums_subtree()` post-order for decay. Uses full recomputation rather than delta propagation (ADR-M-012 decision). ✅ No issues.

### `observe.rs`
10-step pipeline: route → accumulate G.own + V propagation → G-sum recompute → plateau sum → split → rebalance → depth-gates → eviction → plateau normalise → P-I4 repair. Each step clearly spec-referenced. Debug checkpoint assertions between steps. ✅ No issues.

### `split.rs`
`attempt_split()` with 6 guards then either `bootstrap_split()` (first ever split, lone V-root) or `catalytic_split()` (general: 2-node parent → 3-node). Allocation helpers properly isolated. ✅ No issues.

### `decay.rs`
`decay(root, attenuation, q)`: uniform path (q=0, single-pass DFS scale) and selective path (q>0, per-depth factor table). Both paths: recompute G-sums bottom-up → recompute V-intensities → V-I3 rebalance → normalize plateaus + P-I4 repair. Good input validation (`assert` on attenuation, q ∈ [0, N)). ✅ No issues.

### `evict.rs`
Two-part module:

**`evict_tip()`** — 7-step tip removal:
1. Absorb evicted G-node's `own` into parent's `own`
2. Unlink from parent G-node
3. Update parent V-entry + walk violation sources 6/7/8/9
4. Update exposed/evictable flags
5. `vtree_remove_leaf()` — V-Tree structural update
6a–6c. Enqueue violation sources: source 6 (leaf-removal ancestor walk), source 7 (collapse sibling children), source 8 (3→2 remaining sibling children), source 9 (collapse cousins)
7. Deallocate G-node, update `node_count`/`terminal_count`, plateau maintenance

**`plateau_after_evict()`** — complex but correct; three cases for the covering basis element (parent is basis, ancestor is basis, descendant-covered). Adjacent same-depth plateau evacuation before sorted placement prevents incorrect merges. This is the most intricate function in the file.

**`scan_for_candidates()`** — Pre-order DFS, prunes on `has_evictable == false`. Two-phase collect-then-evict (ADR-M-015). ✅ No issues.

### `rebalance.rs`
The largest module (1,478L), clean structure:

- **`ViolationSources`** struct — 10 Boolean flags, each independently toggleable for targeted unit testing. Every public push-helper has a `_with_config` variant.
- **Display wrappers** (`Nd`, `Ch`, `Ctx`) — zero-allocation tracing formatters for `VNode` context.
- **Core operations:** `contract()` (3→2, isolate heaviest), `standard_promote()` (explode 2-child into 3-node parent), `skip_promote()` (elevate past parent to grandparent), `legacy_promote()` (semi-internal entry: create G-child, lift entry to grandparent, install new V-entry). All ops correctly update depth caches and evictable flags.
- **Violation push helpers (sources 3,4,6,7,8,9,10):** Each handles a specific structural context where uncle shields weaken. Collectively exhaustive per §IDEA M-11.11.
- **`escalate_after_promote()`** — Cycle detection: if the heaviest child or its descendants would be violated immediately after standard-promote, contract + optional skip-promote to break the cycle (§IDEA M-11.10).
- **`resolve()`** — §IDEA M-11.9; two-phase: (1) ensure parent is 2-node via contraction, (2) dispatch standard-promote / skip-promote / legacy-promote based on node type and depth gate.
- **`rebalance()`** — Drain loop. Safety-net: `max(20 × node_count, 10_000)` iterations. Debug builds `panic!` on overflow; release builds log and break (reasonable for production). Post-loop O(n) audit runs in debug or when tracing at DEBUG level; `find_violated_nodes()` deepest-first for systematic cleanup.

✅ One note: The doc comment says safety-net floor is 10,000 but the code is `saturating_mul(20).max(10_000)` — `.max` sets a *minimum* of 10,000. The comment wording ("floor at 10,000") is technically correct but may confuse readers who expect `floor` to mean a lower bound vs. upper bound. Consider rewording to "minimum 10,000".

### `vtree.rs`
- **`vtree_remove_leaf()`** — 3 cases: root entry → empty tree; 3-node parent → 2-node; 2-node → structural collapse (sole child replaces parent, depth cache invalidated).
- **`propagate_v_sums()`** / **`recompute_all_v_intensities()`** — upward propagation and full post-order recompute (used by decay).
- **`propagate_evictable_flags()`** — early-exit when flag unchanged.
- **`v_depth()`** — opportunistic caching with path warming (ADR-M-029). Debug-builds validate cache against uncached walk. `Ordering::Relaxed` is appropriate (single-threaded, non-atomic interior mutability pattern).
- **`invalidate_depth_subtree()`** — iterative DFS, early-exit if already stale (ancestor invariant from ADR-M-029 ensures subtree is also stale). ✅ No issues.

### `vnode.rs`
- `VNode<u64>` is exactly 64 bytes (one cache line); compile-time assert confirms this.
- `AtomicU32` for `cached_depth` occupies the 4-byte padding gap between `parent` (4 bytes) and `kind` (48 bytes, align 8) — zero memory overhead (ADR-M-029).
- `PackedChildren<V>` uses SoA layout: `intensities[3]` contiguous for cache-friendly sampling scan; `ids[3]` accessed only after the winner is chosen.
- `is_empty()` on `PackedChildren` has `#[allow(dead_code)]` — always returns `false` for a valid node (len is always 2 or 3). Included for Rust convention; suppressing the lint is fine but a doc comment explaining "never true for a valid node" would help readers.
- Both `const _: ()` size checks use `assert!` — good zero-cost compile-time guards. ✅ No issues.

### `graph_budget.rs`
- **`adjust_depth_gates()`** — D-I3 invariant preserved via fixed buffer. Tighten: floor at `buffer + 1`. Relax: no ceiling. Dead zone (between soft_limit and α_relax × budget) → no change. `soft_limit` recomputed each call from `headroom` and `convergence_bound = 2(D_c − 1)` (ADR-M-018). ✅
- **`evict_candidates()`** — Two-phase collect-then-evict. Re-verifies each candidate before calling `evict_tip()` (slot occupied, still evictable, still exceeds D_evict, not G-root). Per-eviction plateau mirror consistency check in debug. Trailing rebalance + P-I4 repair if any evictions occurred. ✅

### `graph_query.rs`
- **`sample()`** — Weighted V-Tree walk, SoA-optimised hot loop (24 bytes of intensities per structural node). `sample_child()` has correct fallthrough guard for floating-point rounding when `threshold == total`.
- **`get()`** — Infallible point query. Domain clamping (DC-026-4), NaN guard, semi-internal interval trimming (returns uncovered half, not full `[lo, hi)`). Debug assertion validates returned cell contains the clamped coordinate.
- **`range_sum()`** — O(N) recursive descent. Partial overlap pro-rates `g.own` by `overlap_width / node_width` in f64. Recursion depth bounded by N (const generic), safe.
- **`contour_range()` / `contour_range_energy()` / `select_plateaus()`** — Segment-tree style `decompose_basis()` with semi-internal early-selection guard (§CR.8.4): prevents ancestor-descendant double-counting when a semi-internal node has both halves overlapping the query. `debug_assert!` guards double-push. ✅

### Phase 4 Verdict

**No correctness bugs found in any of the 12 core modules.** The implementation is thorough, each function traces back to the spec (§IDEA / ADR references), tracing spans are present throughout, and `debug_assert!` guards verify invariants in test/dev builds. The code is well-structured with single-responsibility modules.

**Minor nits** (non-blocking):
- N1: `PackedChildren::is_empty()` could use a doc comment explaining it always returns `false` for a valid node.
- N2: `rebalance()` safety-net comment says "floor at 10,000" — consider "minimum 10,000" to avoid ambiguity.
- N3: `AtomicU32::cached_depth` comment in `vnode.rs` says "thread safety" — but `GvGraph` is `!Sync`; the `AtomicU32` is used for *interior mutability* (shared-ref caching). The comment could clarify this is for single-threaded interior mutability, not multi-threaded access.
